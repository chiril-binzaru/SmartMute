# SmartMute ML

Offline training pipeline for the sound/silent classifier (step 5 of the implementation
order in `../CLAUDE.md`). Runs on the PC; only the trained model goes to the phone.

## Setup

```
cd ml
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
```

Needs Debian's `python3-venv` package.

## Data

Datasets live in `ml/data/`, which git ignores: they contain real messages and must
never be committed.

- `notification_log_*.csv`: exports from the dev app, how to get them:
  `../docs/PULLING_DATA.md`. Format and columns: `../docs/DATA_SCHEMA.md`.
- `android_message_notifications_200_v3.xlsx`: hand-labelled dataset, `decision` is the
  label. Uses friendly app names (`Telegram`) instead of package names, and has
  `content_type` / `chat_type` / `conversation_state` filled in by hand.

## Pass-through rule

Call notifications (CallStyle template, raw_category call/missed_call,
dialer packages) are never intercepted, cancelled or reposted. They are
excluded from the training set and always pass through untouched.

Detection: `is_call_notification()` in `smartmute_data.py`. A row is a call if
`raw_template` ends in `CallStyle` or `raw_category` is `call` / `missed_call`; a
package in `DIALER_PACKAGES` (fill it in there) is only a fallback, because Telegram,
Viber and WhatsApp calls come under the messenger's own package. `load_export()` and
`load_manual()` drop call rows (`load_export(path, include_calls=True)` keeps them),
`prelabel.py` and `mask.py` drop them and print the count, and `explore.py` reports how
many were excluded. The app keeps logging them.

## Scripts

- `smartmute_data.py`: loaders for both datasets, draft `user_reaction` derivation, the
  rule baseline. Keep in sync with `docs/DATA_SCHEMA.md`.
- `explore.py`: aggregate stats on the newest export and the manual dataset. Prints no
  message text.
- `prelabel.py`: turns an export into a review file. Derives `content_type`,
  `chat_type` and `conversation_state` from the raw columns and text, pre-fills
  `decision` with the rule baseline (`prelabel_rule` says which rule), and sorts by
  `sender_id` for reviewing in batches. Only fills empty cells, so re-running on a
  reviewed file keeps your corrections; never overwrites the input. The heuristics and
  their known gaps (Telegram channels come out as `dm`; the user's own messages aren't
  logged) are documented in the file. Full workflow, including opening and saving in
  LibreOffice Calc: `../docs/LABEL_REVIEW.md`.
- `mask.py`: makes a copy of an export or review file that can be shared, e.g. for
  help with the analysis. See [Masking](#masking).

```
.venv/bin/python explore.py
.venv/bin/python prelabel.py --input data/exports/notification_log_X.csv \
                             --output data/review/notification_log_X_prelabeled.csv
```

## Masking

```
.venv/bin/python mask.py --input data/review/notification_log_X_review.csv \
                         --output data/masked/notification_log_X_masked.csv \
                         --mapping data/private/pseudonyms.csv
```

| Option | Meaning |
|---|---|
| `--input` | Export or review file. Read only, never changed. |
| `--output` | Masked CSV to write. Refuses to replace an existing file unless `--overwrite`. |
| `--mapping` | Pseudonym → original table. **Private: never share or commit it.** If it exists it's reused and extended, so a sender keeps the same pseudonym across exports; use one mapping file for all exports. |

What the masked file contains:
- only the columns in `ALLOWLIST` in `mask.py`; anything else is dropped, including
  columns the app adds later, until they're reviewed and added to the list
- no `message_text`; instead `text_len`, `has_qmark` and `is_emoji_only` (0/1)
- `sender_id` and `raw_conversation_title` as `S01`, `S02`, … (one shared numbering, in
  order of first appearance), `notification_key` as `K01`, `K02`, … (WhatsApp puts the
  contact's phone number in it); `raw_sub_text` dropped (Gmail puts the account address
  there)
- your `role` column as is, if the input has one. It's free text: put a category there
  (`family`, `work`), never a name.

After writing, the script searches the output for every original name, title and key
it replaced. If one is found, it prints `MASKING FAILED` with the columns it was found
in (never the value), deletes the output, leaves the mapping unchanged and exits with
code 3. Short numeric senders (SMS short codes such as `7444`) count only when they
fill a whole cell, as they'd otherwise match inside timestamps.

Not covered: a name that appears only inside a message text (dropped anyway) is not
in the mapping, and timing patterns (`timestamp`, reply delays) stay in the file.

## Tests

Run against fake data only (`testdata/notification_log_synthetic.csv` and
`testdata/notification_log_synthetic_review.csv`, both regenerated by
`testdata/make_synthetic.py`); real exports are never used in tests.

```
.venv/bin/python -m pytest tests
```
